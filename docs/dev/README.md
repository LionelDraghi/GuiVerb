# docs/dev — maintainer-facing documentation

This directory holds what the maintainers need to work on the project:
the workflow, the release parameters, the indexes of open work, and the
structural choices. It is not user-facing documentation: that lives in
[`docs/features/`](../features/) and the other top-level documents.

## In this directory

| File | Role |
|---|---|
| [development_workflow.md](development_workflow.md) | how development work flows through the shared lifecycle |
| [release_procedure.md](release_procedure.md) | local parameter values and additions; the common procedure lives in the [reference repository](https://github.com/LionelDraghi/ada-project-template/blob/main/release_procedure.md) |
| [concerns.md](concerns.md) | lightweight index of concerns and open design questions: id, priority, kind, authoritative link, status |
| [design_discussions.md](design_discussions.md) | structural choices, alternatives, rationale, and status |
| [fixme_index.md](fixme_index.md) | generated FIXME index; regenerated by `make doc`, not hand-edited |
| [ci-strategy.md](ci-strategy.md) | CI strategy for the GUI backends |
| [references.md](references.md) | external work cited as base or grounding: ARIA-AT, WAI-ARIA, Core-AAM, APG |

The former `development-plan.md` now lives as `docs/roadmap.md`.

Stable intent belongs in `docs/manifesto.md`; consolidated design in
`docs/architecture.md`; target findings in `docs/pilot-targets.md`.

The shared rules — responsibilities, naming conventions, proposal
lifecycle, changelog conventions — live in the reference repository,
[`documentation_structure.md`](https://github.com/LionelDraghi/ada-project-template/blob/main/documentation_structure.md),
and apply here in full.
